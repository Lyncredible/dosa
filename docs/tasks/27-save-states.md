# 27 · Guest save states

Dosa owns guest execution and device state in the CPU and DOS libraries. The desktop should pause the guest at an instruction boundary and present explicit save and load actions. Before changing a running session, read and validate the complete file and prepare the devices and mount bindings it references.

| Work | Current state and verification |
| --- | --- |
| CPU payload | Version 1 stores processor profile, register and hidden descriptor state, A20, interrupt shadow, halt state, memory mapping bounds, and physical RAM. The header has a magic tag, a little-endian schema version, and a bounded metadata length. Metadata uses Postcard. RAM follows as raw bytes. Generated guests verify resume, protected paging state, and unchanged CPU state after rejecting malformed or incompatible data. |
| Video and device payloads | The core saves VGA planes, latches, registers, palette, and ANSI state and rebinds the aperture before restoring CPU memory. It preserves elapsed guest time, PIT and PIC, XMS, keyboard, mouse, joystick, PC speaker, and Sound Blaster DMA state. Version 2 restores AdLib envelopes and sample phase by replaying timestamped register writes through Oplon. Version 4 restores configured MIDI synthesis through RustySynth, verifies the SoundFont, and restores MPU-401 acknowledgements and partial messages. PCM matches exactly in the round-trip tests. Each replay is capped at 30 minutes of rendered audio and one million events per guest. State capture beyond these limits remains open. |
| DOS process and media | The core preserves the active process, memory allocator, pending calls, directories, open files and shared seek positions. Live handles on writable directories and ZIP sessions reopen through the mounted root with their original access modes. ZIP session copies preserve archive timestamps. A generated guest resumes a write at the saved offset and verifies that changed media are rejected and the original archive stays intact. ISO mounts are identified by all declared sectors, including raw sectors available through MSCDEX. Version 3 also restores the BIOS disk status on a matching floppy or hard disk boot image. Generated boot sectors verify status and a second-stage read after loading. The combined media scan is capped at 1 GiB. Shared pipeline buffers are stored once per save. |
| File and desktop controls | The View menu uses file pickers to save and restore active guests. The State slots menu offers three local checkpoints. Saves use a staged file and loads cap the file size. The desktop restores batch continuations, shared file positions, and active pipeline stages and buffers. Tests cover slot replacement, isolation, and reopening a slot in a fresh application instance. Automatic saves remain open. |

Slots are stored in `%LOCALAPPDATA%\Dosa\states` on Windows, under `~/Library/Application Support/Dosa/states` on macOS, and under `${XDG_DATA_HOME:-$HOME/.local/share}/dosa/states` on Linux.
