# 27 · Guest save states

Dosa owns guest execution and device state in the CPU and DOS libraries. The desktop should pause the guest at an instruction boundary and present explicit save and load actions. Before changing a running session, read and validate the complete file and prepare the devices and mount bindings it references.

| Work | Current state and verification |
| --- | --- |
| CPU payload | Version 1 stores processor profile, register and hidden descriptor state, A20, interrupt shadow, halt state, memory mapping bounds, and physical RAM. The header has a magic tag, a little-endian schema version, and a bounded metadata length. Metadata uses Postcard. RAM follows as raw bytes. Generated guests verify resume, protected paging state, and unchanged CPU state after rejecting malformed or incompatible data. |
| Video and device payloads | The core saves VGA planes, latches, registers, palette, and ANSI state and rebinds the aperture before restoring CPU memory. It preserves elapsed guest time, PIT and PIC, XMS, keyboard, mouse, joystick, PC speaker, and Sound Blaster DMA state. Version 2 restores AdLib envelopes and sample phase by replaying timestamped register writes through Oplon. PCM matches exactly in the round-trip test. Replay is capped at 30 minutes of rendered audio and one million writes per guest. MIDI state and AdLib states beyond these limits remain open. |
| DOS process and media | The core preserves the active process, memory allocator, pending calls, directories, open files and shared seek positions. Live handles on writable directories and ZIP sessions reopen through the mounted root with their original access modes. ZIP session copies preserve archive timestamps. A generated guest resumes a write at the saved offset and verifies that changed media are rejected and the original archive stays intact. ISO mounts are identified by all declared sectors, including raw sectors available through MSCDEX. Version 3 also restores the BIOS disk status on a matching floppy or hard disk boot image. Generated boot sectors verify status and a second-stage read after loading. The combined media scan is capped at 1 GiB. Shell pipes require additional work. |
| File and desktop controls | The core encodes a versioned payload with a length and CRC checksum. It validates and prepares replacement state before changing the machine. The View menu uses file pickers to save and restore standalone DOS programs. Saves use a staged file and loads cap the file size. A desktop test verifies the restored CPU profile, pause state, and subsequent keyboard input across application instances, plus rejection of a damaged file. Shell continuations, slots, and automatic saves remain open. |
